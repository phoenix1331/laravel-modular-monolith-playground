Add a Training module

Coaches want to post training sessions for their teams. This walks through building that as a new module, from an empty folder to a module that clubs can switch on and the codebase can delete again. Copy the shape of modules/Compliance, the smallest real module, and keep modules/Fixtures open for the annotated reference.

Commands run inside the app container through the Makefile, so make up first. Nothing below edits a file in app/: if you find yourself changing Core to fit a module in, the boundary has slipped.

  1. Decide the key and the dependencies

    The key is how everything else refers to the module: Pennant flag, route names, table prefix, frontend folder. Lowercase kebab case.

    Key training
    PHP folder and namespace modules/Training/, Modules\Training\ (the key in PascalCase)
    Frontend folder resources/js/modules/training/
    Tables Prefixed with the key: training_sessions
    Hard dependencies None: sessions belong to Core teams
    Soft dependencies None yet

    If sessions had to link to fixtures, Training would hard-depend on fixtures and talk to it only through FixtureLookup. If it just wanted to post an announcement when Messaging is around, that would be a soft dependency through an event.

  2. Write the definition

    The definition is what Core reads. It names the module and its dependencies by key, so it never imports another module. 

    modules/Training/TrainingModule.phpnamespace Modules\Training;

use App\Modules\ModuleDefinition;

final class TrainingModule extends ModuleDefinition
{
    public function key(): string
    {
        return 'training';
    }

    public function name(): string
    {
        return 'Training';
    }

    public function description(): string
    {
        return 'Training sessions for each team.';
    }

    public function serviceProvider(): string
    {
        return TrainingServiceProvider::class;
    }
}

    hardDependencies(), softDependencies() and seeder() default to nothing; override them when you need them.

  3. Add the service provider

    The base provider loads Routes/web.php into the club area behind module:training, and Database/Migrations. A module with nothing to bind needs nothing more. 

    modules/Training/TrainingServiceProvider.phpnamespace Modules\Training;

use App\Modules\ModuleDefinition;
use App\Modules\ModuleServiceProvider;

final class TrainingServiceProvider extends ModuleServiceProvider
{
    protected function definition(): ModuleDefinition
    {
        return new TrainingModule;
    }
}

  4. Create the table and the model

    Every module table carries organisation_id, and every model uses BelongsToOrganisation. That one trait scopes reads to the current club and fills the column on create, so one club can never see another's sessions. 

    modules/Training/Database/Migrations/2026_10_10_100000_create_training_sessions_table.phpSchema::create('training_sessions', function (Blueprint $table) {
    $table->id();
    $table->foreignId('organisation_id')->constrained()->restrictOnDelete();
    $table->foreignId('team_id')->constrained()->cascadeOnDelete();
    $table->dateTime('starts_at');
    $table->string('location');
    $table->string('focus')->nullable();
    $table->timestamps();

    $table->index(['organisation_id', 'starts_at']);
});
    modules/Training/Models/TrainingSession.php#[Table('training_sessions')]
#[Fillable(['team_id', 'starts_at', 'location', 'focus'])]
#[ObservedBy(AuditObserver::class)]
class TrainingSession extends Model implements Auditable
{
    use BelongsToOrganisation;

    // casts(), team() relation, auditType(), auditActions()
}

    Foreign keys to Core tables (teams, players, users) are fine. A foreign key into another module's table is not: keep that as a plain id and resolve it through the other module's contract.

  5. Routes, controller, query and policy

    Controllers never build queries; reads go through a class in Queries/. A Pest source scan enforces it. 

    modules/Training/Routes/web.phpRoute::prefix('training')->name('training.')->group(function () {
    Route::get('/', [SessionController::class, 'index'])->name('index');
    Route::post('sessions', [SessionController::class, 'store'])->name('sessions.store');
});
    modules/Training/Http/Controllers/SessionController.phppublic function index(Request $request, UpcomingSessions $sessions): Response
{
    Gate::authorize('viewAny', TrainingSession::class);

    return Inertia::render('training/pages/Index', [
        'sessions' => $sessions->for($request->user()),
    ]);
}

    Put TrainingSessionPolicy in modules/Training/Policies/; Laravel discovers it next to the model's namespace. Use User::coachesTeam() for "is this coach on this team", as every other module does. The page name, training/pages/Index, is the page's path under resources/js/modules.

  6. Install it

    Add the definition to the list. Order does not matter: modules are registered dependencies first. 

    config/modules.php'installed' => [
    // ...
    MessagingModule::class,
    TrainingModule::class,
],
    make migrate
make artisan cmd="modules:list"

    Installed is not enabled. No club can reach /training yet: every route returns 404 until the super admin switches it on.

  7. Give it Deptrac layers

    Two layers, two ruleset entries and a group for the graph. Until you do, make deptrac fails: --fail-on-uncovered and debug:unassigned both catch classes that belong to no layer. 

    deptrac.yamllayers:
    - name: Training
      collectors:
          - type: classLike
            value: ^Modules\\Training\\(?!Contracts\\).*
    - name: TrainingContracts
      collectors:
          - type: classLike
            value: ^Modules\\Training\\Contracts\\.*

ruleset:
    Training:
        - Core
        - Framework
        - TrainingContracts
    TrainingContracts:
        - Framework

formatters:
    graphviz:
        groups:
            Training:
                - Training
                - TrainingContracts

    Had Training hard-depended on Fixtures, its ruleset entry would add FixturesContracts. Never Fixtures.

  8. Add the frontend entry and page

    The registry finds every resources/js/modules/*/index.ts by glob, so there is no list to edit. The link appears only for clubs with Training enabled. 

    resources/js/modules/training/index.tsimport { Dumbbell } from '@lucide/vue';
import { defineModule } from '@/lib/modules';
import training from '@/routes/training';

export default defineModule({
    key: 'training',
    navigation: [
        { title: 'Training', href: training.index(), icon: Dumbbell },
    ],
});

    The page goes in resources/js/modules/training/pages/Index.vue and gets the app layout automatically. It may import shared components, its own files and Wayfinder's @/routes/training and @/actions/Modules/Training helpers. Importing another module's pages or helpers fails make lint-js.

  9. Write tests inside the module

    Tests go in modules/Training/Tests/. They boot the full app against a fresh database, run with the suite while Training is installed, are skipped once it is removed from config/modules.php, and vanish when the folder is deleted. 

    modules/Training/Tests/TrainingTest.phpbeforeEach(function () {
    $this->club = Organisation::factory()->create();
    app(ModuleManager::class)->enable($this->club, 'training');
});

test('coaches see sessions for their own teams only', function () {
    // ...
});

test('a club without training gets a 404', function () {
    // ...
});

    Prefix any helper functions with the module (trainingSession()): Pest loads every test file into one process. For demo data, add Database/Seeders/TrainingSeeder.php and return it from seeder(); it runs on make fresh for clubs that have Training enabled.

  10. Switch it on and prove it detaches

    Log in as super@platform.test (password password), open a club, and enable Training. Then run the gates: 

    make check                               # every gate: Pint, Oxlint, ESLint boundaries, PHPStan, Deptrac, types, tests
make graph                               # redraw docs/modules.png with the new box
make uninstall-check MODULE=Training     # delete it in a temp copy and run every gate again

    The last one is the real test of the design. If anything outside modules/Training and resources/js/modules/training still mentions the module, it fails and names the file. Add Training to the uninstall matrix in .github/workflows/ci.yml so CI keeps proving it.
