# Context

Tutorial repo: a Laravel 13 + Vue 3 modular monolith for grassroots sports clubs. Feature modules switch on or off per organisation (club) and can be deleted from the codebase without breaking the rest of the app. Boundaries are enforced by Deptrac and Pest arch tests, not by convention.

Primary audience is people learning how to draw and enforce module boundaries in Laravel, so code that defines a boundary is annotated to explain why it exists and how a new module would follow the same pattern.

## Core principles

| Principle                        | Meaning                                                                                                                                |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Core knows nothing about modules | Organisations, users, roles, teams, players, flags, module registry and audit log live in Core. Core never imports from `Modules\`     |
| Modules talk through contracts   | Each module's `Contracts/` folder (interfaces, DTOs, events) is public. Everything else is internal                                    |
| Installed is not enabled         | Installed: the definition class is listed in `config/modules.php` and its provider registers. Enabled: a per-organisation Pennant flag |
| Boundaries are enforced          | Deptrac (PHP), Pest arch tests (rules inside a module) and `eslint-plugin-boundaries` (frontend) fail the build on violations          |

## Runtime

| Service      | Container port | Host port                | Notes                                      |
| ------------ | -------------- | ------------------------ | ------------------------------------------ |
| `app`        | 8000           | `APP_PORT` (8000)        | FrankenPHP serving `public/`               |
| `app` (Vite) | 5173           | `VITE_PORT` (5173)       | HMR, browser connects via `localhost:5173` |
| `mysql`      | 3306           | `FORWARD_DB_PORT` (3307) | Host 3306 was already in use               |

- Container main process is `php artisan dev --inline` (server, queue, logs, Vite)
- `AppServiceProvider` overrides the `server` dev command to `frankenphp php-server` so `php artisan dev` stays the single entry point while FrankenPHP serves requests
- Container runs as the host UID/GID (build args) so bind-mounted files stay host-owned
- Fresh volume needs `migrate` before the queue worker stops logging missing-table errors
- `make check` runs every gate: Pint, `vp check`, PHPStan, Deptrac (+ unassigned), vue-tsc, Vitest, Pest
- The entrypoint deletes `public/build` and `public/hot` on boot. Without `public/hot`, Laravel silently serves a stale production build; with no build present it fails loudly instead. Use `make build-check` (builds, then deletes `public/build`) rather than leaving a build behind
- If menus or pages look out of date, check `public/hot` exists (`make restart` recreates it)

## Decisions: setup and tooling

| Decision                                            | Why                                                                                                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Kit taken from `laravel/vue-starter-kit:dev-main`   | Tagged releases (v1.x) target Laravel 12 and Tailwind 3. Main is what `laravel new --vue` installs for Laravel 13                           |
| Kit auth features trimmed at install                | Admins create users and players never log in, so self-registration, email verification, 2FA and passkeys add surface without teaching value |
| Kit `.github/` and `pnpm-workspace.yaml` not copied | CI is written around the boundary checks; the container uses npm                                                                            |
| Skeleton `CLAUDE.md` / `AGENTS.md` removed          | They instructed host PHP installs, which conflicts with the Docker-only workflow                                                            |
| PHPStan memory limit 1G                             | Default 128M crashes the parallel workers                                                                                                   |
| Model date docblocks use `CarbonImmutable`          | The kit sets `Date::use(CarbonImmutable::class)`                                                                                            |
| `vp check` formats YAML and Markdown too            | Run `npx vp check --fix` in the container after editing them; tables get padded columns                                                     |
| Husky hooks are POSIX `sh`                          | Husky 9 runs hooks with `sh` (dash on Ubuntu), ignoring the shebang, so bashisms like `&>` misbehave                                        |
| Faker locale `en_GB`                                | UK grassroots clubs                                                                                                                         |

## Decisions: tenancy and roles

| Decision                                                 | Why                                                                                                                                                                                       |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/` has no landing page                                  | Guests go to `/login`, signed-in users to `User::homeUrl()`. The kit's `Welcome` page was removed; the route keeps the name `home` for logo links and logout                              |
| Teams and players are always visible to club users       | They are Core, not a module, so feature flags never hide them. Flags gate modules only                                                                                                    |
| `User::coachesTeam()` is the one coach check             | Used by `TeamPolicy` and every module policy instead of each repeating the `team_user` query                                                                                              |
| Test factories never generate readable literal names     | `TeamFactory` uses `{surname} {age group}` so random names cannot collide with names tests set explicitly (caused a 1-in-6 flaky failure)                                                 |
| Roles as a backed enum (`App\Enums\Role`)                | `worker` and `admin` belong to one organisation; `super_admin` belongs to none. Players are records, never users                                                                          |
| Role/organisation invariant in `User::saving`            | Breaking it throws `InvalidUserOrganisation`. `role` and `organisation_id` are not mass assignable                                                                                        |
| Areas split by route group + `role` middleware           | `/dashboard` etc. for `admin,worker`, `/platform` for `super_admin`; wrong role gets 403. Per-action rules live in policies                                                               |
| Login destination varies by role                         | `LoginResponse` + `User::homeUrl()`, also used by `redirectUsersTo` and shared to Vue as `auth.home`                                                                                      |
| `role` and `module` gates run before route model binding | `prependToPriorityList(before: SubstituteBindings::class)`. Otherwise the tenant scope 404s a bound model before the role check, and disabled modules query their tables before answering |
| Single-database tenancy                                  | `organisation_id` + `BelongsToOrganisation`. Super admin bypasses with `Model::withoutOrganisationScope()`, never implicitly                                                              |
| Scope fails closed                                       | No current organisation (guest, super admin, console without `CurrentOrganisation::set()`) matches no rows                                                                                |
| Writes guarded too                                       | Creating fills `organisation_id`; another club's id or changing it on update throws `CrossOrganisationWrite`                                                                              |
| `CurrentOrganisation` is a scoped singleton              | Resolves from the signed-in user; jobs/console/seeders use `set()` or `runAs()`                                                                                                           |
| `User` is not scope-guarded                              | Auth resolves the user through the model and `CurrentOrganisation` resolves through the user, so it would be circular. User lists filter explicitly (`ClubWorkers`)                       |
| Teams and players are Core                               | Every module hangs off them. `team_user` links workers to teams; workers see assigned teams only (`TeamPolicy::view` and `VisibleTeams`)                                                  |
| Organisation checked twice                               | Binding goes through the scope (404); policies also compare `organisation_id`                                                                                                             |
| Validation rules filter by organisation                  | `unique`/`exists` rules bypass the Eloquent scope                                                                                                                                         |
| Inertia props are shaped arrays plus a `can` object      | Pages never receive hidden columns; buttons follow the same policies as the server                                                                                                        |
| Query objects, not repositories                          | Eloquent is active record; query objects name reads that carry rules. Cross-module access goes through contract interfaces returning DTOs, which is where persistence is swappable        |
| Seeders set `organisation_id` explicitly                 | `WithoutModelEvents` disables auto-fill, guards, the User invariant and auditing. `SeedDataTest` proves the data still obeys the rules                                                    |

## Decisions: modules

| Decision                                                                           | Why                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Soft dependencies go through Core capabilities                                     | The contract lives in Core (`App\Capabilities\MembershipStatus`) because Core must bind the null default and never imports modules. Consumers (KitShop) type-hint the Core interface, so there is no module-to-module edge for Deptrac to see |
| Capability null answers mean "not tracked, allow"                                  | `NullMembershipStatus` reports everyone paid up, so a club without Subscriptions is never blocked                                                                                                                                             |
| Provider override is `bind` with a per-resolve enabled check                       | Installed = the provider rebinds; enabled = the closure checks `ModuleManager` for the current club each time. `singleton` would leak one club's answer to the next (probed: the `runAs` test fails)                                          |
| Modules own their console commands and schedule                                    | Registered in the module provider (`commands()`, `callAfterResolving(Schedule::class)`), so they vanish when the module is uninstalled                                                                                                        |
| Console work runs per club via `CurrentOrganisation::runAs()`                      | No signed-in user means no current organisation and an empty scope; `subscriptions:check-overdue` loops clubs with the module enabled and runs as each                                                                                        |
| Overdue announcements are idempotent                                               | `overdue_notified_at` marks a fee once, so a daily run never re-fires `PaymentOverdue` for the same fee                                                                                                                                       |
| Payment gateway is internal, not a contract                                        | Only Subscriptions charges money, so `PaymentGateway` lives in `Payments/`. `FakePaymentGateway` approves everything; `declineNext()` drives the failure path                                                                                 |
| Money in integer pence                                                             | `amount_pence` column; the form takes pounds and `ChargeTeamRequest::amountPence()` converts                                                                                                                                                  |
| Seeded module flags are keys in `ClubSeeder::CLUBS`, filtered by what is installed | Enabled through `ModuleManager` in dependency order, so the same rules apply and an uninstalled module is skipped rather than breaking the seed. Toggles are audited                                                                          |
| Core gating tests never name a module                                              | `SeededModuleGatingTest` discovers gated pages from the router (`module:{key}` middleware) and expected modules from the registry + seeder. Module-specific scenarios live in the module's own tests                                          |
| Arch rules about method calls are source scans                                     | Pest arch only sees which classes are used, not which methods are called. `sourceViolations()` reports `file:line` for raw queries, controller queries and string container keys. Each rule was probed with a deliberate violation            |
| Controllers never build queries (Core included)                                    | `TeamRoster`, `FixturesForUser::upcoming()/recent()`, `FixtureFormOptions::team()`, `ReportSheet::allInTeam()` hold the reads. Writes on models stay in controllers/actions                                                                   |
| `DB::transaction()` allowed, raw query methods banned                              | Raw queries bypass `OrganisationScope`                                                                                                                                                                                                        |
| Sibling modules never see each other                                               | Availability and MatchReports both depend on Fixtures only; neither ruleset lists the other. Probed: MatchReports using `AvailabilityResponse` fails Deptrac                                                                                  |
| Module test helpers are prefixed with the module                                   | Pest loads every test file into one process, so two modules defining `scheduleFixture()` would be a fatal redeclare                                                                                                                           |
| No foreign keys into another module's tables                                       | `availability_responses.fixture_id` is an opaque id resolved through `FixtureLookup`; a DB constraint would couple the schemas. FKs to Core tables are fine                                                                                   |
| Dependent modules route by plain id, not a bound model                             | `/availability/fixtures/{fixture}` takes an int and resolves it via `FixtureLookup` (404 for another club); binding `Fixture` would import Fixtures' internals                                                                                |
| Cross-module data joined in PHP, not SQL                                           | `UpcomingAvailability` merges `FixtureData` with its own responses; a SQL join would read Fixtures' table                                                                                                                                     |
| A dependent module's ruleset lists its dependency's Contracts layer only           | `Availability: [Core, Framework, AvailabilityContracts, FixturesContracts]`; probed: using `Fixtures\Models\Fixture` fails Deptrac                                                                                                            |
| Module tests treat other modules as black boxes                                    | Availability tests schedule via `POST /fixtures` and read via `FixtureLookup`, never Fixtures' factories                                                                                                                                      |
| Module tests live in `modules/{Name}/Tests`                                        | `Modules` PHPUnit suite + `pest()->in('../modules/*/Tests')`; excluded from Deptrac (`exclude_files`) and PHPStan (`excludePaths`). Deleting a module deletes its tests                                                                       |
| Module tables prefixed with the module key                                         | `fixtures_fixtures`, `fixtures_venues` via `#[Table]`; factories via `#[UseFactory]`                                                                                                                                                          |
| Module internals layer uses a negative lookahead                                   | `^Modules\\Fixtures\\(?!Contracts\\).*` for internals, `^Modules\\Fixtures\\Contracts\\.*` for the public layer. Contracts may use Framework only                                                                                             |
| Cross-module reads return DTOs                                                     | `FixtureLookup` returns `FixtureData`; `Fixture::toData()` builds it. Models never cross the boundary                                                                                                                                         |
| Public events carry DTOs                                                           | `FixtureScheduled` holds `FixtureData`; dispatched from `ScheduleFixture` so every way of scheduling fires it                                                                                                                                 |
| Coaches manage fixtures for their own teams                                        | Module rule layered on Core: viewing a fixture defers to Core's `TeamPolicy`; managing needs admin or assigned coach. Venues are admin-only                                                                                                   |
| Core `Team` has no `fixtures()` relation                                           | Relations point from module to Core only                                                                                                                                                                                                      |
| Dependencies declared by key string                                                | `hardDependencies(): ['fixtures']`, never `FixturesModule::class`, so declaring a dependency does not import another module                                                                                                                   |
| Registry validates at boot                                                         | Non-definitions, malformed or duplicate keys, missing hard dependencies and cycles throw `InvalidModuleConfiguration`                                                                                                                         |
| `ModuleRegistry` is framework-free                                                 | Unit tested without Laravel (`tests/Unit/Modules`)                                                                                                                                                                                            |
| Module conventions by folder                                                       | `ModuleServiceProvider` loads `Routes/web.php` (club middleware + `module:{key}`) and `Database/Migrations`; policy discovery finds `Modules\{Name}\Policies\{Model}Policy`                                                                   |
| Enabled = Pennant flag `module:{key}` per `Organisation`                           | `features` table, scope `organisation\|{id}` via `FeatureScopeSerializeable`. Defined per installed module, off by default                                                                                                                    |
| `ModuleManager` is the only way to toggle                                          | Enforces hard dependency rules (`ModuleDependencyNotEnabled`, `ModuleHasEnabledDependents`), exposes `blockersFor*`, audits each toggle                                                                                                       |
| `isEnabled()` also checks hard dependencies                                        | Stays correct if flags are edited directly in the database                                                                                                                                                                                    |
| Disabling only flips the flag                                                      | Module tables are untouched, so data survives off/on                                                                                                                                                                                          |
| Disabled module routes return 404                                                  | A disabled module should look like it does not exist, not like a permission error                                                                                                                                                             |
| `module:{key}` added by the base provider                                          | Every module route is gated without the module opting in                                                                                                                                                                                      |
| `enabledModules` Inertia shared prop                                               | `[{key, name}]` for the current club in dependency order; empty for the super admin and guests                                                                                                                                                |
| Module page names = path under `resources/js/modules`                              | `Inertia::render('fixtures/pages/Index')`. `app.ts` resolves `./pages/{name}` then `./modules/{name}`; `config/inertia.php` page paths include `js/modules`                                                                                   |
| Module nav from `index.ts`, shown only when enabled                                | `navigationFor()` filters by `enabledModules` and optional per-link `roles`                                                                                                                                                                   |
| Super admin toggles via `ModuleManager`                                            | `PUT /platform/organisations/{organisation}/modules/{key}`; dependency exceptions become a `module` validation error; blockers are computed server-side for the UI                                                                            |
| Platform counts bypass the scope explicitly                                        | `PlatformOrganisations` uses `withoutGlobalScope(OrganisationScope::class)` for team counts                                                                                                                                                   |
| Deptrac `Framework` layer for vendor namespaces                                    | `--fail-on-uncovered` would flag every vendor dependency. Core's ruleset is `[Framework]`: vendor code yes, module layers never                                                                                                               |
| Deptrac layers collected by namespace                                              | Directory regexes match absolute paths; the container mounts at `/app`, so `app/.*` also matched `/app/modules/...`                                                                                                                           |
| `make deptrac` also runs `debug:unassigned`                                        | Catches a new class or folder that belongs to no layer                                                                                                                                                                                        |
| `modules:list` command                                                             | Shows installed modules in dependency order                                                                                                                                                                                                   |

## Decisions: audit log

| Decision                                                          | Why                                                                                                        |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Observer-driven, adapted from `phoenix1331/laravel-audit-logging` | Models implement `Auditable` and add `#[ObservedBy(AuditObserver::class)]`; no audit code in controllers   |
| Subject type is a string, not a Core enum                         | A Core enum would have to list module models (`fixtures.fixture`)                                          |
| Stored in MySQL `audit_logs`                                      | One database for the stack; no foreign keys so history outlives records                                    |
| Entry organisation = record's `organisation_id`                   | Falls back to `CurrentOrganisation`, so super admin edits to club data land in that club's trail           |
| Append-only                                                       | `AuditLog` throws on update and delete                                                                     |
| Not audited                                                       | Hidden attributes, timestamp-only updates, query-builder bulk writes, pivot changes (`team_user`), seeders |
